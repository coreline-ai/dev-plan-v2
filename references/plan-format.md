# 간단한 개발 계획 형식

계획은 구현을 위한 짧은 Markdown 체크리스트다. 데이터베이스나 상태 머신이 아니다.

필수 섹션:

1. `개발 목적`
2. `범위`
3. `제외 범위`
4. `참조`
5. `실행 규칙`
6. 하나 이상의 `Phase N. 이름`
7. `QA 체크리스트`
8. `실행 기록`

각 Phase에는 최소 한 개의 체크리스트를 둔다. 권장 항목은 변경 범위, 완료 기준,
테스트 방법이다.

```markdown
## Phase 1. 로그인 오류 수정
- [ ] 오류 처리 구현
  - 변경 범위: src/auth/**
  - 완료 기준: 잘못된 토큰이 명확한 오류를 반환
  - 검증: pytest tests/auth
```

계획 체크는 Lead가 실제 diff와 테스트를 확인한 뒤 갱신한다. 테스트하지 못한 항목은
`미실행`으로 기록한다. 상세 audit evidence, attempt ID, workspace hash는 사용하지
않는다.
